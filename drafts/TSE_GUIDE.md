# 東証のしくみ — 自動公開 手順書（TSE_GUIDE.md）

クラウドルーティン **tse-daily-auto** が毎日読む正式手順書。1日1本、日本の株式市場の「制度と手続き」の解説記事を生成→コンプラ＆品質ゲート→白なら自動公開、危ういものは公開せずエスカレ。
**人が編集する＝SYNC_FILES入り。** ⚠️ 発火エンジン・signal_lab系・固定オラクル・6コアHTMLには触れない（実行のみ）。

> 発足の経緯: 2026-08-31、投資格言シリーズが**2度目のキュー枯渇**（44本で和の相場格言をほぼ網羅・
> 8/19 の補充に続き 8/27〜8/31 に5日連続枯渇）となり、水増しではなく後継シリーズへ枠を渡す判断をした。
> 既存362本を本文までgrepしたところ、**TOB・呼値・立会外分売・議決権行使は言及ゼロ**、
> ストップ高・適時開示・市場区分・貸株・逆日歩・単元未満株は**脇役の一言しかなく主役の記事はゼロ**だった。
> 一次情報の到達性も確認済み（`jpx.co.jp` 200 / `fsa.go.jp` 200・2026-08-31 手元実測）。
> 🚨 **クラウド側の到達は結果が違いうる。初回の担当が測り直し、結果を TSE_LEDGER.md に書くこと。**

## 0. このシリーズの狙い（品質の芯）

**「知らないと損をする。しかし、調べれば必ず分かる」ものだけを扱う。**相場観も予測も要らない領域で、
格言シリーズと同じ役割＝**覚えやすい入口を提供し、既存の深掘りガイドへ送客する**。

⚠️ **薄コンテンツ厳禁**。「用語＋一言」では絶対に出さない。各記事は必ず：

- ① その制度は何のためにあるか ② **手順または数字の具体例**（仮の設定で「こう動く」を示す）
- ③ 個人投資家にどこで効いてくるか ④ 自分で一次情報を確かめる手順（どのページのどこを見るか）
- ⑤ よくある誤解 ⑥ まとめ＋関連ガイド
- **インラインSVG概念図を最低1枚**（ライト/ダーク両対応・`※概念を示すイメージ図です`明示）
- 8〜10分の読み応え。手本＝`guide-proverb-atama-shippo.html`（構造・nav・免責を丸ごと踏襲）。

🚨 **このシリーズだけの絶対条件（格言シリーズとの最大の違い）:**

- **制度の数値は、必ず一次情報を開いて確かめる。**値幅制限の幅・呼値の刻み・上場基準の数値・
  日程の日数などを**思い出しで書かない**。一次情報＝`jpx.co.jp` / `fsa.go.jp` / `e-Gov`（法令）/ 各社IR。
- **本文に「確認日」を必ず書く**（例：「2026-08-31 時点のJPXの規定では」）。**制度は変わる。**
- **一次情報に届かなかったら、その回は書かずにエスカレする。**二次情報だけで制度を書かない。
- **個別の銘柄・個別のTOB案件・個別の証券会社を評価しない。**制度の説明に徹する。

## 1. 記事テンプレ（厳守）

**`guide-proverb-atama-shippo.html` の `<head>`〜`<style>`〜nav〜フッター〜スクリプトを丸ごとコピーし、本文と `<head>` メタ（title/description/canonical/OG/JSON-LD）だけ差し替える。**

- ファイル名：`guide-tse-<slug>.html`（slugはキュー参照）
- nav は10ボタン・`guides.html` を current。冒頭 `disclaimer-banner`、本文末 `p[data-disclaimer="kinsho-v1"]`、フッターにも `kinsho-v1`。
- 数値例には必ず「考え方を説明するための仮の例」注記。SVGには `<title>` と figcaption 末尾に「※概念を示すイメージ図です。」。
- 断定/将来予測/特定銘柄の売買推奨は禁止。一般論・教育として書く。結論は「〜に近づく/つながる」と非断定。

## 2. 毎日の手順

1. `date -u` → JST(+9) で基準日。
2. **次に書く題材を決める**：下の【キュー】を上から見て、`drafts/tse/TSE_LEDGER.md` と `guides.html` のどちらにも未登録（＝`guide-tse-<slug>.html` がまだ無い）最初の1件を選ぶ。
   - ★既に当日分の `guide-tse-*.html` をこの実行で作っていれば**何もしない**（1日1本）。
   - ★キューが尽きたら**新しい題材を勝手に作らない**。`TSE_LEDGER.md` に「🚩キュー枯渇・補充依頼」を記録してエスカレし終了（水増し＝薄コンテンツ＝厳禁）。
3. **一次情報を先に開く。**§0の絶対条件のとおり、書く前に `jpx.co.jp` 等の該当ページを実際に取得する。
   - 取得できたURLと確認日を、記事本文と `TSE_LEDGER.md` の両方に残す。
   - **取得できなければ、記事を書かずに手順9へ**（理由に「一次情報に到達できず」と、叩いた先と応答を書く）。
     🚨 遮断の種類を必ず書き分ける＝`CONNECT tunnel failed` 等＝**経路（許可リスト）**／`cf-mitigated` 等の応答ヘッダ付き403＝**先方のbot判定**。⚠️ **UA偽装での迂回はしない。**
4. テンプレに従い `guide-tse-<slug>.html` を作成（§0・§1 の厚みを必ず満たす）。
5. 【コンプラ自動公開ゲート】Agentツールで **model=opus** のサブエージェント（Read,Edit・`.claude/agents/compliance-reviewer.md` ペルソナ）に監査させる：①黒/グレー/白 ②グレーは軽微修正（表現軟化・免責追加のみ／事実・数値・SVG・構造は不変）をEditで適用 ③適用後に再読し最終判定 ④黒 or 要協議なら編集せず「エスカレ」。返り値＝【初期/適用修正/最終】。
6. 【品質ルーブリック】`QUALITY_RUBRIC.md` の5観点で自己採点。⚠️は表現・構成・補足1文だけで自己修正（数値/SVG/主張/免責は不変）、❌はエスカレ。
7. **公開判定**：初期=白 もしくは（グレー→opus軽微修正→最終=白）かつ ルーブリック合格 のときのみ進む。さらに別の fresh な **model=opus** サブエージェント（Readのみ・同ペルソナ）で「そのまま公開して白か」を独立確認。白でなければ手順9。

   【公開前の決定論チェック（全て満たす／欠けたら手順9）】① `kinsho-v1` 免責が 冒頭＋本文末＋フッター ②禁止語なし（必ず/絶対/確実/100%/儲かる/一択/今すぐ買い 等）③特定銘柄の買い/売り推奨なし ④SVGに「概念図」明示・数値に「仮の例」明示 ⑤**制度の数値に一次情報のURLと確認日が添えてある**。
8. **公開**：
   - a. `python publish_article.py --file guide-tse-<slug>.html --category "東証のしくみ" --emoji <絵文字> --card-title "<題>" --desc "<1行説明>"`
   - b. `python check_site_consistency.py; echo EXIT=$?`（赤なら中止しエスカレ）
   - c. `git add guide-tse-<slug>.html guides.html generate_market_news.py sync_to_github.py drafts/ && git commit -m "feat: 東証のしくみ auto-publish <slug>" && git push origin main`
   - d. `drafts/tse/TSE_LEDGER.md` に「✅公開済み・題材・slug・コンプラ判定・**一次情報URLと確認日**」を追記しコミット＆push。
9. **エスカレ（公開しない）**：記事を `drafts/tse/draft-<slug>.html` に `<meta name="robots" content="noindex,nofollow">` 付きで保存し、`drafts/tse/TSE_LEDGER.md` に「🚩要人間レビュー（理由）」を記録して `git add drafts/tse/ && git commit -m "chore: tse escalate <slug>" && git push origin main`。

   > 🔒 **🔴黒のときだけの例外**：このリポジトリは **public** で `raw.githubusercontent.com` から誰でも本文を読める。
   > よって **🔴黒（法務リスク）と判定した本文はリポジトリにコミットしない。**台帳には日付・対象・理由の要約だけを書く。
10. 最後に日本語要約：選定した題材・一次情報の到達可否・コンプラ判定・公開有無・ファイル名。

## 3. 絶対厳守

- **1日1本まで**（当日分の `guide-tse-*.html` が既にあれば何もしない）。
- **キュー枯渇時は水増し公開しない**＝エスカレして補充を待つ。
- **一次情報に届かなければ書かない。**制度を二次情報で書くのは、このシリーズで最もやってはいけないこと。
- 6コアHTML（index/calendar/charts/vix/market-health/hot-assets）・political-feed・track-record・sitemap.xml に直接触れない。
- 発火エンジン(`generate_technical_alerts.py`)・signal_lab系・固定オラクル(`signal_lab_verify.py`/`check_site_consistency.py`/`publish_article.py`)は**書き換えない（実行はOK）**。
- 推奨・利益示唆・断定（必ず/絶対/保証/儲かる/一択）禁止。**情報提供であり投資助言ではない。**
- 少しでもエラー・事実未確定・コンプラの迷いがあれば**公開せずエスカレ（安全側）**。
